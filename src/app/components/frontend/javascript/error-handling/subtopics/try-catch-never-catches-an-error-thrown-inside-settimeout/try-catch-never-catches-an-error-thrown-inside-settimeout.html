try/catch Never Catches an Error Thrown Inside setTimeout

A try/catch only protects code running while its own call stack frame is active — by the time a scheduled callback runs, that frame is long gone.

See it run

A global window.onerror handler proves the "escaped" error is real by catching it — while the local catch block wrapping the setTimeout() call never fires at all.
