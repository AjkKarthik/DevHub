Spreading a Prototype in a Mixin Breaks instanceof

Replacing a prototype with a spread creates a new object and severs existing instances' link to it — and since class methods are non-enumerable, the spread silently drops them too.

See it run

The same mixin is applied two ways — a broken spread-based reassignment and the correct Object.assign mutation. Watch instanceof and the original class's own methods before and after.
