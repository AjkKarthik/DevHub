Number Input's Empty Value for Invalid Text

Typing "1e" into a number input isn't blocked — but reading .value back reports an empty string, not "1e".

See it run

Setting a number input's value to a legal-but-incomplete number string ("1e") produces an empty .value — even though every character in it is individually valid number syntax.

Where this fits

This sanitization behavior is part of the same browser-graceful-degradation family as the next subtopic — unsupported input types silently falling back to text rather than erroring. After that, see how step mismatches surface as a checkable validity state rather than being silently blocked.
