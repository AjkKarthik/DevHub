Unsupported Types Fall Back to Text

An unrecognized type keyword never errors — it silently resolves to "text", provable by reading el.type back.

See it run

Set type to a made-up keyword, then read it back — the browser reports what it actually applied, not the string you requested.

Where this fits

This silent-fallback pattern is the same family of graceful degradation as the previous subtopic's value sanitization. The final subtopic looks at a case where the browser does the OPPOSITE of silently ignoring a problem — step mismatches produce a real, checkable validity flag.
