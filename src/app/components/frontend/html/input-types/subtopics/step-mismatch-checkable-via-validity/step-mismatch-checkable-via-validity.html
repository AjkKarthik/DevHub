step Mismatch Is Checkable via Validity

An off-step value isn't rejected or rewritten — it stays exactly as set, flagged invalid through a real ValidityState.

See it run

Set values on and off a step="2" boundary, and read .validity.stepMismatch/.checkValidity() to see the browser's built-in constraint check in action.

Where this fits

This closes out the three input-types gotchas: value sanitization silently empties invalid numbers, unsupported types silently downgrade to text, and step violations do neither — they're kept and flagged instead. Return to the Input Types & Attributes overview for the full picture.
