Font preload Without crossorigin Fetches the Font Twice

CSS font requests always use CORS mode. A preload without crossorigin never matches that mode — so the browser downloads the font a genuine second time.

See it run

A font is preloaded WITHOUT crossorigin, then requested again by an @font-face rule. Inspect the Resource Timing entries to see whether the browser reused the preload or fetched twice.

Where this fits

This is one of two ways a rel="preload" tag can quietly fail to do its job — the next subtopic covers the other one, where the hint is ignored outright rather than merely duplicated. Return to the Head & Metadata overview for the full picture.
