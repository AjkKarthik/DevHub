The First @layer Encountered Sets Its Position, Not Declaration Order

A layer block filled in before the explicit order statement locks its position immediately — the later order statement can't move it.

See it run

Compare computed color to reveal that a layer's position came from its first source-order appearance, not the later explicit order list.

Where this fits

This is the main page's own first "Common Mistake" made directly measurable via computed styles, completing the trio of cascade-layer priority gotchas alongside unlayered-styles and !important reversal.
