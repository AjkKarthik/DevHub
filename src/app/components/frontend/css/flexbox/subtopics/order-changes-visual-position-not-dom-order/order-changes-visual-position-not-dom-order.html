CSS

order Changes Visual Position, Not DOM Order

Reordering items visually with order leaves DOM traversal — and therefore Tab-key order — completely untouched, provably.

See it run

Compare DOM order against visual order (sorted by rendered position) for three items reshuffled with order — the two genuinely diverge.

Where this fits

This closes out three flexbox sizing and ordering gotchas — implicit minimum sizes overriding flex-shrink, flex-basis silently overriding width, and order creating a real visual/DOM divergence with accessibility consequences. Return to the CSS Flexbox overview for the full picture.
