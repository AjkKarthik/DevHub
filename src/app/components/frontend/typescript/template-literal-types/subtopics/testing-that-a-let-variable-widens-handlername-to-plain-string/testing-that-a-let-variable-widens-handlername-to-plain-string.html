Testing That a let Variable Widens HandlerName to Plain string

A generic version of the main page's HandlerName pattern silently loses its literal specificity when called with a let-declared variable instead of a const or literal.

See it run

Call a generic makeHandlerName<E> with a const literal, then with a widened let variable, and compare the resulting return types.

Where this fits

This connects the main page's HandlerName example directly to its own separate Common Mistake #2, showing the exact mechanism (generic inference from a widened variable) that triggers it silently.
