Testing That OptionalToNullable Detects Implicit undefined

Unlike the previous two subtopics' findings, OptionalToNullable correctly handles a plain optional property with no explicit "| undefined" written anywhere.

See it run

Apply the main page's own OptionalToNullable<T> to an interface with a plain optional property and confirm it — and only it — becomes nullable.

Where this fits

This closes out the mapped types topic by confirming not every conditional-type filter on this page has the same optional-property gap — the direction of the extends check is what matters.
