Testing That as const's Readonly Is Compile-Time Only, Not Runtime

The main page's code comment says an as const object "is Readonly — no mutation allowed" with no qualifier — but that guarantee only holds for code the TypeScript compiler actually checks.

See it run

Compare an as const object against an Object.freeze()'d one — bypass TypeScript's type checking on both and see which one actually stops the mutation.

Where this fits

This is the same literal-type-narrowing behavior the main page introduces — the distinction that matters here is scope: a compile-time guarantee only protects the code the compiler actually sees, which is a different, narrower promise than a runtime one.
