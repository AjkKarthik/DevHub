Testing That PluginRegistry Never Verifies plugin.name Matches Its Key

The challenge's "fully type-safe, no casts needed" registry keys its internal Map by plugin.name at runtime — a value the generic type parameter K never actually checks against.

See it run

Register a plugin whose name field doesn't match the key it's registered under, and see which key it actually ends up filed under — with no compile error either way.

Where this fits

This builds on the page's own keyof/generic patterns — a generic constraint like K extends keyof TMap & string is a real, useful safety net for the SHAPE of a value, but it is not a substitute for validating a specific runtime property against that same key.
