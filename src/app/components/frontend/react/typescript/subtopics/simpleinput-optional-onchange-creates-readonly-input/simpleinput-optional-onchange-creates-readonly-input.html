Testing That SimpleInput's Optional onChange Can Silently Create a Read-Only Controlled Input

The main page marks SimpleInput's onChange as optional in its type — this checks whether that type-level optionality is also safe at the React/DOM level when value is passed without it.

See it run

The main page's own SimpleInput, rendered with value but no onChange — a combination its type fully permits.

Where this fits

This is the last of three subtopics testing the exact boundary between what TypeScript's type system verifies and what only shows up at runtime — a type assertion's broken promise, a discriminated union's compile-time-only guarantee, and now an optional prop with a React-level consequence TypeScript can't see.
