ErrorBoundary.Recover() Clears the Error, Not the Child's Own State

Recover() only resets the boundary's own error flag and re-renders — the same child instance keeps whatever state caused the original exception.

Where this fits

The main Error Handling page's mistake list already tells you to call Recover() when the user takes corrective action — this subtopic explains exactly what Recover() does and doesn't do, since assuming it re-runs the child's lifecycle is a common and confusing trap. Next: unlike most lifecycle exceptions ErrorBoundary can recover from, an exception thrown inside Dispose or DisposeAsync is deliberately treated as fatal, by design.
