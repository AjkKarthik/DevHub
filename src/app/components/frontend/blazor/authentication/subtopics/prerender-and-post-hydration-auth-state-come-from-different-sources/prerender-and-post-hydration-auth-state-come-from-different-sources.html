Pre-render and Post-Hydration Auth State Come From Different Sources

Static SSR pre-render reads HttpContext.User; the interactive circuit reads its own, separately persisted state — and the two can disagree.

Where this fits

The previous subtopic covered NotifyAuthenticationStateChanged as the trigger that re-evaluates already-rendered AuthorizeView components — this one covers a related but distinct timing gap: the auth state itself can come from two different sources depending on rendering phase, and without explicit persistence across that boundary, the interactive side can disagree with what pre-render already showed.
