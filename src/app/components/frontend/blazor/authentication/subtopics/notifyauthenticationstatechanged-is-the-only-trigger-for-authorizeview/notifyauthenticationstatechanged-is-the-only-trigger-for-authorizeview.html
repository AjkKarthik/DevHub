NotifyAuthenticationStateChanged Is the Only Trigger for AuthorizeView

AuthorizeView and [Authorize] don't poll for auth changes — they subscribe to one event, raised by NotifyAuthenticationStateChanged, and nothing else.

Code Examples

Where this fits

The main Authentication page's mistake list already tells you to call NotifyAuthenticationStateChanged after login — this subtopic explains WHY that call is required at all: it's the only thing that raises the event every AuthorizeView and [Authorize] component in the app is subscribed to. The next subtopic builds on this by looking at a related but distinct timing issue — where the auth state itself comes FROM differs between server pre-render and post-hydration, which can disagree even when notifications are wired correctly.
