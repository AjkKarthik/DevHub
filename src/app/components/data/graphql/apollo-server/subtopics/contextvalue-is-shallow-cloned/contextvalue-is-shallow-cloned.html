executeOperation’s contextValue Is Shallow-Cloned, Not Shared by Reference

Verified by installing a real Apollo Server and reading its own compiled source: the contextValue object you pass to executeOperation is never the same object your plugins mutate.

Code Examples

Where this fits

This closes out the apollo-server batch's third and final verified finding: a plugin's mutation of requestContext.contextValue can never leak back to the object the caller of executeOperation originally passed in, because Apollo Server clones it internally before any plugin ever sees it.
