The 100 Cap Belongs to the Driver, Not the Server

The main page's own mistake block calls 100 "the server's connection limit" — verified against the real driver and server defaults, that number belongs to the driver, and it's a very different figure from the server's own ceiling.

Where this fits

Closing every MongoClient properly is still the right fix either way — but knowing which number is actually at risk (a driver-side cap on ONE client, not a single shared server total) changes how urgently a team should treat a leak, and sets up the next subtopic's own look at another prose-only mechanism: optimistic concurrency control.
