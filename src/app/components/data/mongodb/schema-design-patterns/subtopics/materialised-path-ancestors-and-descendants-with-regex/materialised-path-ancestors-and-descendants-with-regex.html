One of the main page's own QnAs names all four tree-structure patterns in one dense paragraph with zero code for any of them — this subtopic builds Materialised Path specifically, the one the QnA calls out as easiest for ancestor/descendant queries.

Where this fits

Materialised Path trades write cost (moving a subtree means updating every descendant's own path string) for read simplicity — a tradeoff worth weighing against the main page's own Parent Reference pattern, which is cheap to update but needs multiple queries to walk down a subtree.
