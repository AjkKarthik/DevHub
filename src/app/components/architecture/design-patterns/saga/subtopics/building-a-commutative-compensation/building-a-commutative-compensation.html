Where this fits

This closes out three concerns the main page names but doesn't fully build out: getting the DATA an event carries right (the first subtopic), ORDERING irreversible steps around the pivot (the second), and now making sure a compensation itself stays correct no matter what order it lands in. All three are different facets of the same underlying trade-off — a Saga gives up the single global lock a 2PC transaction would provide, in exchange for these explicit, application-level correctness responsibilities.
