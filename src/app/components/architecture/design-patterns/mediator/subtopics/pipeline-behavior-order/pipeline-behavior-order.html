Pipeline Behavior Execution Order

The main page's own mistake block tells you to register pipeline behaviors for validation, logging, and transactions — but only ever shows one. With two or more, the order they're registered in silently decides which one wraps which.

Where this fits

Together with Publish()'s own execution-order behavior, this closes out the "what actually happens at runtime" gap in the main page's MediatR coverage — Send() through an ordered pipeline of behaviors, and Publish() through a sequential (by default) list of notification handlers.
