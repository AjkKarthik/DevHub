Decision heuristics

  • Start simple: Monolith → Modular Monolith → Microservices — move right only when pain justifies complexity.
  • Sync vs Async: Prefer synchronous REST/gRPC for simple request-response; adopt async messaging only when temporal decoupling or fan-out is genuinely needed.
  • DDD is for complex domains: If your domain is simple CRUD, DDD overhead is not justified. Apply when multiple teams work on overlapping models.
  • Resilience patterns always apply: Circuit breaker and Outbox are not optional in production microservices — add them from the start, not after incidents.
  • Migration patterns are exit ramps: Strangler Fig and ACL are tools for escaping legacy systems — only relevant if you have legacy to escape.
