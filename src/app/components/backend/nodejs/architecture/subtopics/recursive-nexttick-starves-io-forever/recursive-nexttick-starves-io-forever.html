Recursive nextTick Starves I/O Forever

The nextTick queue drains completely — including newly-added callbacks — before any other phase runs, so a self-scheduling callback never lets the loop advance.

Where this fits

The main page's theory already states nextTick callbacks "run before the next event loop phase" — this subtopic shows exactly what that guarantee costs when a callback keeps rescheduling itself. Next: UV_THREADPOOL_SIZE only takes effect if set before the first call that actually needs the thread pool, not simply "before Node starts" as commonly assumed.
