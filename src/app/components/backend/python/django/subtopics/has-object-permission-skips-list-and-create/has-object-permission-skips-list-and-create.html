has_object_permission() Skips List and Create

has_object_permission() only runs when a view calls get_object() — list() and create() never do, so an object-level-only permission class silently protects nothing for either action.

Where this fits

The main page's own challenge builds IsOwnerOrReadOnly using has_object_permission() alongside IsAuthenticatedOrReadOnly for the detail routes — this subtopic shows exactly where that pattern needs a second, different mechanism to cover list and create.
