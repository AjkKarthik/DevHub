ProcessPoolExecutor Can’t Pickle Closures or Lambdas

Bridging CPU-bound work into a process pool sends the callable across a real process boundary by pickling it — and lambdas and closures fail that step in a way threads never expose.

Where this fits

The main page's own theory says CPU-bound bridging needs a "self-contained" task with "picklable args/returns" — this subtopic shows exactly what breaks when that rule is violated, and why the same code can work fine with threads first. The final subtopic moves to a subtler limit: the default thread pool that asyncio.to_thread() itself quietly shares and caps.
