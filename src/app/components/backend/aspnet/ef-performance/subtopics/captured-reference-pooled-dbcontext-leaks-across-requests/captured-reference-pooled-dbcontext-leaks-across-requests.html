A Captured Reference to a Pooled DbContext Leaks Across Requests

The main page warns against storing state ON a pooled DbContext. A subtler variant: capturing a REFERENCE to the instance itself in a fire-and-forget Task. Since pooled instances are reset and reused, not destroyed, the stale reference silently operates on a future, unrelated request's context.
