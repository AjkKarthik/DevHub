Signal-Based Services — The Modern State Pattern

Private writable signal, public readonly view, computed() for anything derived — plus providedIn: 'root' vs component-scoped, a decision that actually changes behavior.

See it run

A shared TodoService with pending/completed/ progress all derived via computed(), plus an effect() that logs a persistence step on every change.

Where this fits

This service pattern handles STATE. The remaining two subtopics go back to the form itself — first the validators that decide what counts as valid input, then the touched/dirty/status flags that control when to actually show errors to the user.
