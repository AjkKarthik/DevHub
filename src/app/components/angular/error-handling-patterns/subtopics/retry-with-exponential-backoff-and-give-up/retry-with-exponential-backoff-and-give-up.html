Retry with Exponential Backoff and a Give-Up State

A flat retry delay can pile more load on a struggling server — exponential backoff, selective retry by status, and a distinct "we gave up" message solve that.

See it run

resilientGet() retries only transient statuses with a growing delay (1s, 2s, 4s, 8s...) and gives up immediately on non-retryable errors like 404.
