Building a Worker Pool for Parallel Task Dispatch

The main topic's "reuse one worker" advice handles sequential calls. A worker pool solves a different problem — running a BATCH of independent tasks truly in parallel.

See it run

20 square-number tasks are dispatched at once — the pool distributes them across navigator.hardwareConcurrency - 1 workers, running several in parallel.

Where this fits

Once several workers are running concurrently, actually diagnosing a stuck or slow one becomes harder — the final subtopic covers debugging and profiling workers directly in DevTools.
