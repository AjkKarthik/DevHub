Auth Interceptor & Token Refresh

Attaching a token to every request is the easy 80% — refreshing an expired one exactly once, even when three requests 401 at the same instant, is the interview question.

See it run

Fire 3 parallel requests against a simulated expired token — watch the console: the refresh call fires exactly once, shared across all three, thanks to shareReplay(1).

Where this fits

Auth is one specific interceptor concern — the next subtopic covers the more general pattern of centralizing error handling (403, 5xx, offline) for every request in one place, instead of repeating status-code branching in every component.
