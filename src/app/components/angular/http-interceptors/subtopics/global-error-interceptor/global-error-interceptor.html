Global Error Interceptor — One Place for Cross-Cutting Failures

403, offline, and 5xx deserve one consistent reaction across the whole app — with an explicit opt-out for the specific requests that want to handle their own error instead.

See it run

One failing call goes through the global interceptor's logging; the second, marked with SKIP_ERROR_TOAST, is handled entirely by the component instead.

Where this fits

The same HttpContext opt-out mechanism used here for error handling is also how a global loading spinner knows which requests to ignore — the last subtopic.
