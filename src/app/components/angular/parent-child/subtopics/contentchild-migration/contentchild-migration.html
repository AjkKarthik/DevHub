contentChild() & Migration Patterns

The mirror image of viewChild() — reading content the PARENT projected in — plus the mostly-mechanical rules for migrating a whole component off the old decorator APIs.

A Tabs wrapper reading its projected <app-tab> children via contentChildren() to build a tab bar.

You've completed Parent-Child Communication

input() flows data down, output() flows events up, model() does both at once, viewChild() reaches into a component's own template, and contentChild() reaches into whatever a parent projected in. Combined with the two migration rules — never mix @Input() with input(), and prefer shared state over deep prop-drilling — that's the complete modern component-communication toolkit.
